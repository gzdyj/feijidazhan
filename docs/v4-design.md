# 飞机大战 第四版 · 手机端性能与画面优化设计文档

> 版本：v4.0
> 创建时间：2026-08-13
> 状态：已完成

---

## 一、问题描述

手机浏览器游玩时，画面整体偏"糊"（模糊/发虚），且**越到后面的波次越明显**：
敌机、子弹、粒子、光效变多后帧率明显下降，拖影与卡顿叠加。

## 二、根因分析（Review 结论）

| # | 根因 | 定位 |
|---|------|------|
| 1 | **canvas 无 devicePixelRatio 适配**：画布像素=CSS 像素，高分屏手机（DPR 2~3）被浏览器放大上采样 → 静态模糊 | 原 `resize()` |
| 2 | **shadowBlur 滥用**：敌机/子弹/粒子逐实体开阴影，后期实体量暴涨 → GPU 填充率飙升 → 掉帧拖影 | `draw()` 各分支 |
| 3 | **实体无上限**：玩家子弹 / 敌机 / BOSS 弹幕 / 道具 / 飘字无限累积 | `fire()` / `spawnEnemy()` / BOSS 弹幕函数 |
| 4 | **每帧重建背景渐变 + 每帧 getElementById 查 HUD** → GC 与 DOM 开销 | `draw()` / `update()` |

**未实现/失效项**：
- `S.control==='touch'` 触屏模式**没有移动逻辑**（只有 mouse 分支跟随指针）→ 手机选"触屏拖拽"飞机无法移动
- canvas 无 `touch-action:none`（iOS 会触发滚动/双击缩放）
- 无切后台自动暂停（来电/切 App 白死）
- AudioContext 未在首次手势时 resume（iOS 无声）
- 射击音效无节流（弹幕武器每秒 ~70 个音频节点）
- 无任何画质自适应/降级机制

## 三、优化方案

### 3.1 DPR 高清渲染
- `resize()`：canvas 物理尺寸 = CSS 尺寸 × `min(devicePixelRatio, dprCap)`，配合 `ctx.setTransform(dpr,...)`
- 游戏逻辑坐标保持 CSS 像素不变，不侵入玩法数值

### 3.2 画质自适应系统（4 档）
| 档位 | shadowBlur | DPR 上限 | 粒子上限 | 星数 |
|------|-----------|---------|---------|------|
| 高(3) | 开 | 2 | 300 | 120 |
| 中(2) | 开 | 1.5 | 260 | 110 |
| 中低(1) | 关 | 1 | 200 | 90 |
| 低(0) | 关 | 1 | 120 | 70 |

- `loop()` 统计 60 帧窗口实测帧率：<40fps 降一档，>55fps 升一档（滞回防抖动）
- 阴影开关：所有 `ctx.shadowBlur` 赋值收敛到 `SB(v)`，关闭时一律 0（省去逐实体阴影渲染）
- 粒子/星数随档位变化，背景渐变改为 resize 时缓存一次

### 3.3 实体上限（防止后期堆积）
- 玩家子弹 ≤160、敌机 ≤32、道具 ≤20、飘字 ≤50、单机敌弹 ≤120（超限从头部裁剪）

### 3.4 移动端体验补全
- 触屏模式跟随指针（`S.control!=='keyboard'` 时均跟随，触屏事件已写入 mouseX/Y）
- canvas `touch-action:none` 防滚动/缩放
- `visibilitychange` 切后台自动暂停
- 首次 `pointerdown/touchstart` 解锁 AudioContext
- 射击音效 50ms 节流
- 触屏设备默认操作方式自动设为"触屏拖拽"
